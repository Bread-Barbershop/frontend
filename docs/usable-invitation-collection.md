# 홈에서 제작까지 이어지는 초대장 컬렉션

홈 카드, 미리보기, 편집기 전체 템플릿 선택과 오른쪽 표지 목록은 `shared/data/invitationTemplates/catalog.ts`의 동일한 23개 디자인을 사용합니다. 결혼식 12종, 세미나 5종, 생일 4종, 돌잔치 2종입니다.

## 디자인

모든 초대장을 가리던 공통 봉투 도입을 없앴습니다. 신문 지면, 흑백 사진, 파란 여백, 정원 프레임, 서신, 에디토리얼, 큰 활자, 엽서, 사진 콜라주, 산책 기록, 레드 포스터, 가든 카드, 컨퍼런스, 입장권, 다크 프로그램, 레드 프로그램, 대화집, 디너, 폴라로이드, 케이크 클럽, 숫자 포스터, 성장 앨범, 첫 생일 카드로 각각 구성했습니다.

표지는 `collectionPosters.ts`의 글자·도형·사진으로 구성하며 SVG 미리보기와 Fabric 편집 데이터가 같은 좌표와 내용을 사용합니다. 사진은 비율을 유지하여 중앙으로 자르고 기존 사진 교체 슬롯을 제공합니다. 인쇄물의 모든 글자와 도형을 편집할 수 있습니다. 기존 생성 사진 및 보유 이미지 자산을 사용했으며 신규 생성 이미지는 없습니다. 출처와 생성 기록은 `showcase-assets.md`, `showcase-stationery-design.md`를 참고하세요.

본문은 기존 네이티브 블록과 편집기에서 선택할 수 있는 기본·종이·라운드·테두리 카드 스타일로 구성합니다. `bulkData.sectionStyle`에 초대장 기본 스타일을 저장하고 새로 추가한 블록에도 적용합니다. 일괄 편집에서 기본 스타일을 바꾸고 상세 편집의 카드 디자인에서 `props.sectionStyle`로 개별 지정하거나 초대장 스타일을 다시 따를 수 있습니다. 공용 `InvitationChapter`가 편집기, 별도 미리보기, 템플릿 미리보기와 공개 화면에 같은 설정을 적용합니다. 구형 저장 데이터의 `props.collectionStyle`은 호환용으로 읽습니다. 새 템플릿은 공통 카드 설정을 사용합니다. 제목·본문 글꼴, 색상, 일정, 사진, 문구도 공용 빌더를 사용합니다. 템플릿 예시의 이름·일정·장소는 사용자가 변경할 수 있는 샘플입니다.

## 제작 흐름

미리보기의 **이 템플릿으로 시작하기**는 `/editor?template=showcase-N`으로 이동합니다. 선택 ID를 URL에 두어 OAuth 팝업, 권한 재요청, 새로고침 뒤에도 유지합니다. 기존 로그인·개인정보 안내·Drive 권한 UI를 사용하고 인증이 완료되면 해당 디자인의 포스터와 본문으로 초기화합니다. 유효한 세션은 추가 확인 없이 진입하며 만료된 세션은 같은 경로에서 다시 로그인합니다. 잘못된 ID는 오류 안내를 보여주고 빈 초대장을 만들지 않습니다.

공통 별도 design UI guide 문서는 저장소에 없었습니다. 기존 제품의 `bg-bg-plain`, `text-text-*`, 둥근 기본 CTA와 인증 모달을 재사용하고 '이 템플릿으로 시작하기', '로그인하고 시작하기'로 문구를 통일했습니다. 기존 1340px 이상 PC 편집 제한은 유지하며 홈의 좁은 화면 CTA에 PC 제작 안내를 표시합니다.

편집기의 카테고리 템플릿은 확인 후 표지와 본문 전체를 바꿉니다. 오른쪽 **표지 디자인 선택**은 확인 후 표지만 바꾸고 본문·업로드 사진·본문 글꼴과 배경을 유지합니다. 둘 다 기존 캔버스 롤백 및 중복 요청 방지를 사용합니다.

인증 완료 후 서버 세션을 갱신해 헤더의 로그인 상태도 함께 바꾸되, 준비한 포스터와 블록 ID는 유지합니다. 갤러리에서 샘플 사진을 남겨 편집할 때 샘플 URL은 블록 안에 유지하고 실제 `File`만 업로드 큐에 넣습니다. 새 사진과 샘플 사진의 혼합, 샘플 재정렬·일부 삭제, 기존 Drive 파일 재사용을 저장 훅 테스트에서 확인합니다.

## 검증 범위

관련 Jest에서 23개 템플릿의 고유 ID, 새 UUID, 미리보기와 편집 데이터의 일치, 로컬 이미지 경로, 편집 가능한 표지, JSON 저장 후 게스트 파싱, 로그인·세션 만료·Drive 권한 재요청·취소·새로고침·잘못된 ID, 표지만 적용 시 본문 보존을 확인합니다. 실제 Google 계정에 대한 저장·공개 발행은 실행하지 않습니다.

전체 빌드·타입 검증과 전체 Jest는 GitHub Actions Frontend Gate에서 관측합니다. 전체 Jest의 기존 실패 7건은 별도로 대조해야 하며, 게이트 성공만으로 전체 테스트 성공이라고 보고하지 않습니다.
