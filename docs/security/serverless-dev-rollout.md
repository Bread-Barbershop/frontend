# 서버리스 인증·저장 전환: dev 적용

## 범위와 배포 조건

별도 Node 서버 없이 Next.js Route Handler를 Vercel 함수로 실행한다. 일반 로그인 인증 정보는 암호화된 HttpOnly 쿠키에만 보관한다. Upstash에는 업로드 진행 정보와, 작성자가 별도로 켠 초대장의 하객 접수용 Google 연결만 암호화해 저장한다. 함수 메모리는 요청 내 중복 조회를 줄이는 용도로만 사용하며 영구 저장소로 사용하지 않는다.

이 브랜치의 로그인·저장 흐름은 새 서버 세션을 요구한다. **dev의 아래 설정과 재로그인을 끝내기 전에는 로그인·저장 기능을 사용할 수 없다.** 서버 세션을 비활성화하면 로그인 시작과 콜백은 503으로 중단되며, 새 Google 토큰을 예전 인증 쿠키 방식으로 발급하지 않는다. `AUTH_SERVER_SESSIONS=false`만으로 새 저장 코드를 구버전 동작으로 전환할 수는 없다. 운영에는 이 코드와 설정을 함께 검증한 후 별도 승격한다. 이번 작업은 운영 환경변수·Redis·배포를 변경하지 않는다.

## dev 환경변수

Vercel의 dev 브랜치 Preview 환경에만 등록한다. 개발용 별도 Redis DB를 권장한다. 기존 숏링크 Redis 환경변수로 자동 대체하지 않는다.

| 이름                                       | 값/설명                                                            |
| ------------------------------------------ | ------------------------------------------------------------------ |
| `AUTH_SERVER_SESSIONS`                     | `true`                                                             |
| `AUTH_REDIS_REST_URL`                      | 개발용 Upstash REST URL                                            |
| `AUTH_REDIS_REST_TOKEN`                    | 개발용 Upstash REST 토큰                                           |
| `AUTH_REDIS_NAMESPACE`                     | `invia:dev:auth:v1`                                                |
| `AUTH_ENCRYPTION_KEY`                      | 무작위 32바이트의 Base64 문자열. **Vercel 서버 환경변수에만 저장** |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 개발 환경용 OAuth 설정                                             |

키는 `NEXT_PUBLIC_` 이름으로 만들지 않는다. 코드·Git·Upstash에 원본 키를 저장하지 않는다. 운영과 개발에 다른 키를 사용한다. Preview에서 `prod`/`production`이 포함된 namespace를 사용하면 실패하도록 방어한다. 같은 Redis URL에 개발 namespace를 쓸 수는 있으므로 DB 자체의 분리는 설정 담당자가 확인해야 한다.

개발 키는 로컬에서 다음 명령으로 생성해서 환경변수 관리 화면에 넣을 수 있다. 출력은 채팅이나 로그에 공유하지 않는다.

```powershell
rtk proxy node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64'))"
```

Google OAuth에 개발 도메인의 `/api/auth/callback`을 redirect URI로 등록한다. URL이 매번 바뀌는 Preview 대신 고정 개발 도메인을 권장한다. 로그인 후 이전 형식의 토큰 쿠키를 지우고 서버 키로 봉인한 HttpOnly 로그인 쿠키를 발급한다. 기존 로그인은 자동 이전하지 않고 재로그인한다.

## 데이터·권한 경계

- 로그인 쿠키는 AES-256-GCM, HttpOnly, Secure(Vercel), SameSite=Lax로 보호한다. 절대 만료는 로그인 후 30일이다. 갱신 응답은 로그인 쿠키를 재생성할 수 없다. 로그아웃은 해당 브라우저의 쿠키를 삭제한다. 유출된 쿠키 사본까지 즉시 철회해야 한다면 Google 권한을 철회한다.
- 일반 로그인은 Google 인증 정보를 Upstash에 쓰지 않는다. 하객 접수 동의 시에만 초대장별 토큰을 별도 암호화하여 한국 시간 D+4 0시까지 저장한다. 암호화 키는 Vercel에 둔다.
- Google Sheets API를 활성화한다. 공개 읽기는 전용 스프레드시트의 CSV 게시 주소를 익명으로 조회하므로 별도 읽기 키를 요구하지 않는다. OAuth 앱이 외부 Testing 상태라면 Drive 리프레시 토큰은 7일에 만료되므로 운영 기간 검증에 반영한다.
- 요청 scope는 `openid drive.file`. 과거의 더 넓은 Drive scope가 반환되면 새 연결을 거절한다. 필요하면 Google 계정에서 이전 연결을 해제한 뒤 재로그인한다.
- 파일 접근은 소유권, 삭제 여부, 앱 전용 `appProperties`, 실제 부모 체인을 검사한다. 이름만 같은 다른 파일을 관리 대상으로 삼지 않는다.
- 기존 버전이 만든 이미지·음악은 파일 자체에 앱 표시가 없을 수 있다. 호환을 위해 검증된 초대장 하위의 에셋을 허용한다. Google이 이미 앱에 허용한 파일이라는 사실과 앱 내부 리소스 검증은 서로 다른 방어다. 무조건 ‘생성한 파일만 접근 가능’이라는 보장은 하지 않는다.

## 저장과 복구

1. 클라이언트가 첫 요청 전에 초대장 UUID를 만들고 로컬 초안에 기록한다.
2. 준비 단계는 계정별 잠금으로 직렬화하며 같은 UUID의 폴더/파일을 재사용한다.
3. 서버가 고정된 대상의 Google resumable upload를 시작한다. 미디어는 브라우저에서 Google로 전송하고 Bearer 토큰을 전달하지 않는다.
4. 파일 ID를 업로드 시작 전에 할당하고 암호화된 업로드 journal에 저장한다. 응답 유실 시 같은 파일 ID를 재사용한다. journal과 resumable URI는 7일 동안 보관한다.
5. 브라우저는 2MiB 단위로 전송한다. 재시도 때 Drive에 받은 바이트 범위를 조회한다. 임시 URI는 업로드 권한이므로 로그/분석 도구에 남기지 않는다.
6. 완료 API가 Google 메타데이터의 실제 소속·종류·크기를 확인한다. 클라이언트가 보낸 완료 선언이나 파일 ID를 신뢰하지 않는다.
7. 미디어가 하나라도 실패하면 data.json을 덮어쓰거나 자동 공개하지 않는다. 작은 JSON은 서버에서 HTML을 정화한 뒤 저장한다. 2MiB 초과 JSON은 앱이 만든 임시 Drive 파일로 직접 전송하고 서버가 최대 32MiB까지 읽어 검증·정화한 뒤 본문에 반영한다. 완료 기록을 남긴 뒤 임시 파일 삭제를 시도하므로 응답이 유실돼도 같은 본문 파일로 복구한다. 이전 썸네일은 본문 저장 전에 삭제하지 않는다.
8. 필요한 저장 단계 성공 후 현재 정책대로 자동 공개한다. data 저장·공개 단계와 업로드 상태를 Redis에 기록한다. Drive와 Redis 사이에 분산 트랜잭션은 없으므로 장애 시 완료 응답이 유실될 수 있고 재시도와 실제 리소스 검증으로 복구한다.

사진·음악을 포함한 로컬 초안은 IndexedDB에 보관한다. 파일 내용·이름·Drive ID와 포스터의 blob URL을 복구한다. 다른 계정에서는 이전 계정 초안을 불러오지 않는다. 마지막 수정 후 7일인 초안은 다음 방문에 정리한다. 로그아웃 시 해당 계정 초안 삭제와 epoch 갱신을 한 트랜잭션으로 처리해서 다른 탭의 이전 저장 요청을 차단한다.

브라우저 저장 공간 부족·사이트 데이터 삭제·시크릿 모드·저장소 강제 정리까지 복구를 보장하지 않는다. 저장 오류는 편집기에 표시한다. 입력 후 자동 저장 지연은 약 750ms이며 탭을 숨길 때 추가 저장을 시도한다. 저장 버튼은 가능한 로컬 저장을 먼저 완료한 후 Drive 요청을 시작한다. 종료 직전의 모든 입력이 반드시 기록된다고 설명하지 않는다.

## 검증 및 운영 승격

로컬에서는 변경 경로의 Jest/ESLint만 실행한다. 전체 빌드·타입 검사·전체 테스트는 dev 대상 PR의 `Frontend Gate`로 확인한다.

실제 dev 설정 후 확인할 항목:

- 새 로그인, 만료된 access token 갱신, 로그아웃 후 재접속.
- 브라우저 Network와 쿠키에 Google access/refresh token이 노출되지 않는지 확인.
- 큰 사진/음악 저장, 전송 중 새로고침 후 재시도, Google upload URI의 CORS/Range 동작 확인.
- 악성 HTML 초대장 렌더링, 외부 파일 ID 삭제·공개·수정 요청 거절.
- 초안의 사진·음악·포스터 복구와 계정 전환, 다른 탭을 연 상태에서 로그아웃.
- Redis 일시 장애 후 로컬 초안 유지 및 재시도, 공개 성공 후 기존 공유 링크 확인.
- Upstash 사용량/Google 오류를 확인한다. 세션·journal·잠금도 Redis 명령을 사용하므로 무료 사용량 내라고 사전에 단정하지 않는다.

설정 전 PR 빌드에서 보안 기능이 실서비스에 연결됐다고 간주하지 않는다. 롤백은 코드와 환경설정을 함께 이전 배포로 되돌린다. 운영 Redis나 운영 암호화 키를 개발 테스트에 사용하지 않는다.

## 고지와 로그인·로그아웃의 구분

- 일반 개인정보 안내의 ‘알겠어요’·Esc·바깥 클릭은 안내만 닫는다. 닫기를 로그인 시작이나 동의로 취급하지 않는다.
- 로그인 화면은 인증 정보의 이용 목적·암호화 보관·최대 30일 보관·로그아웃 시 해당 세션 정보 삭제를 먼저 설명한다. ‘동의하고 Google로 계속하기’를 누를 때 Google OAuth를 시작한다. 취소·Esc·바깥 클릭은 OAuth를 시작하지 않는다.
- 화면에서는 쉬운 표현을 사용하고, 실제 저장 업체인 Upstash와 Vercel의 역할, 세션·진행 정보·로컬 초안의 보관 기준은 `/policy`에 설명한다.
- 로그아웃은 현재 세션과 해당 기기의 계정별 로컬 초안을 삭제한다. Google 접근 권한은 자동 철회하지 않는다. 현재 연결 해제 방법은 Google 계정 권한 관리 페이지로 안내하며, 앱 자체의 연결 해제 API는 이번 작업에 포함하지 않는다.
- Google 토큰 철회는 해당 사용자가 같은 Google Cloud 프로젝트에서 승인한 다른 OAuth 클라이언트·세션에도 영향을 줄 수 있다. 향후 앱 자체 연결 해제를 구현할 때는 로그아웃과 별도 동작으로 제공하고, 영향을 받는 계정 연결과 저장본을 함께 정리한다.
- 운영에 새 고지문을 적용하기 전 서버 세션 환경변수가 활성화돼 있고 실제 보관 방식·기간과 방침이 일치하는지 확인한다. 기존 방침의 변경 공지 기준도 운영 승격 시 확인한다. Preview 빌드 성공만으로 이 검증을 대신하지 않는다.

## 하객 접수

작성자가 먼저 초대장을 저장한 뒤 편집기의 ‘초대장 설정’에서 예식일과 받을 항목을 고르고 동의한다. 가족·친구용 링크는 대표 초대장에 연결된 방명록과 사진함을 공유한다. 독립 복제본은 별도로 설정한다.

- 이름·메시지·작성일만 담는 전용 스프레드시트를 내 드라이브에 생성한다. 이 파일 전체를 링크가 있는 사용자에게 읽기 전용으로 공유한다. 다른 탭이나 개인정보를 추가하지 않도록 안내한다. 방명록 등록은 원자적인 Sheets batchUpdate로 텍스트 행과 중복 방지 기록을 함께 추가한다.
- 사진은 내 드라이브의 별도 비공개 폴더로 보낸다. 매번 소유자 전용 권한과 실제 초대장 공개 상태를 확인하고, 정상 사진 종류·크기·횟수에 한해 파일 하나의 전송 주소를 발급한다.
- D+4 자정 이후 새 쓰기를 거절한다. 마감 전에 발급한 사진 업로드 세션은 자체 만료까지 완료할 수 있다. 이미 받은 글과 사진은 Drive에 남고 방명록은 공개 공유를 유지하는 동안 토큰 없이 읽힌다.
- 실제 dev 계정으로 설정 동의, 일반 로그아웃, 40일 이후 유효한 연결, 동시 작성·응답 유실 후 재전송, 비공개 사진함, 두 기능 모두 끄기, Google 권한 철회, 마감 전후를 확인한다. CI의 모의 응답과 별도로 검증한다.
