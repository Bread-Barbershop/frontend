# 갤러리 샘플 페이지 설계 방향

## 목적

갤러리 페이지는 사용자가 초대장을 처음부터 구성하지 않아도 되도록, 미리 완성된 샘플 초대장을 제공하는 공개 페이지다.

사용자는 샘플을 둘러보고, 미리본 뒤, 선택한 샘플 데이터를 기반으로 에디터에 진입해 바로 수정할 수 있어야 한다.

## 기본 전제

- DB를 사용하지 않는다.
- 샘플 초대장 데이터와 자산은 프로젝트 정적 파일에 포함한다.
- 갤러리 페이지는 실제 사용자 저장본이 아니라 제작자가 준비한 템플릿성 샘플을 보여준다.

## 데이터 구성

샘플 초대장은 다음 자산으로 구성한다.

1. 메인 포스터 이미지
2. 초대장 본문 JSON 데이터
3. 선택적 이미지/음원 자산

메인 포스터는 Fabric JSON을 갤러리에서 실시간 렌더링하지 않는다. 완성 이미지로 구워 정적 파일로 제공한다.

초대장 본문은 기존 게스트 렌더러가 조립할 수 있는 JSON payload 형태로 제공한다. 이 JSON에는 `blocks`, `bulkData`, `shareUrl`, `bgm` 등 렌더링에 필요한 데이터가 포함된다.

샘플 JSON 안의 이미지와 음원은 Google Drive fileId가 아니라 `/samples/...` 정적 URL을 사용한다.

## 추천 파일 구조

```txt
public/
  samples/
    manifest.json
    wedding_01/
      data.json
      poster.webp
      bgm.mp3
      images/
        gallery_01.webp
        gallery_02.webp
```

`manifest.json`은 갤러리 목록에 필요한 최소 정보만 가진다.

```json
{
  "samples": [
    {
      "id": "wedding_01",
      "title": "클래식 웨딩",
      "category": "wedding",
      "thumbnailUrl": "/samples/wedding_01/poster.webp",
      "dataUrl": "/samples/wedding_01/data.json"
    }
  ]
}
```

## 렌더링 방식

갤러리 목록에서는 manifest와 썸네일 이미지만 로드한다.

샘플 상세 미리보기에서는 선택한 샘플의 `data.json`을 fetch하고 다음을 조립해서 보여준다.

- 메인 포스터: 정적 이미지
- 본문: 기존 block 기반 렌더러
- 배경/폰트/공유 정보: 샘플 JSON의 `bulkData`, `shareUrl`
- 음원: 샘플 JSON의 `bgm`

## 에디터 진입

샘플 선택 후 에디터로 이동할 때 기존 저장본 수정 라우트인 `/editor/[id]`는 사용하지 않는다.

샘플은 아직 Google Drive에 저장된 초대장이 아니므로 새 작성 흐름인 `/editor`에 샘플 식별자를 붙인다.

```txt
/editor?sample=wedding_01
```

에디터는 `sample` 쿼리가 있으면 해당 샘플의 `data.json`을 정적 경로에서 불러오고, editor store와 Fabric 초기 데이터를 샘플 값으로 초기화한다.

사용자가 저장하기 전까지는 일반 새 초대장과 동일하게 취급한다. 저장 시점에만 Google Drive 폴더와 UUID를 새로 생성한다.

## UI 요구사항

- 라우트는 `/gallery`다.
- 로그인 여부와 관계없이 접근 가능하다.
- 상단 공통 헤더 메뉴에서 진입할 수 있다.
- 본문 좌우 padding은 `40px`이다.
- 갤러리 스크롤 영역은 공통 헤더와 푸터 사이에 고정한다.
- 문서 전체가 아니라 갤러리 내부 컨테이너만 세로 스크롤한다.
- 스크롤바 트랙은 투명 처리해서 배경 이미지가 이어져 보이게 한다.

## 타이틀 박스

- 헤더 기준 약 20% 아래에 배치한다.
- 페이지 좌측에 붙인다.
- 내부 텍스트도 좌측 정렬한다.
- 내부 padding은 `32px`이다.
- 홈/대시보드에서 사용하는 글래스모피즘 스타일을 따른다.

텍스트:

```txt
Invitation Designs
초대장 갤러리
다양한 디자인을 둘러보고 원하는 초대장으로 시작할 수 있어요.
```

기준 스타일:

```tsx
rounded-4xl border border-white/30 bg-white/15 p-8 text-left backdrop-blur-md
```

기준 shadow:

```css
box-shadow:
  inset 4px 4px 18px rgba(0, 0, 0, 0.08),
  inset -4px -4px 18px rgba(255, 255, 255, 0.75);
```

## 카테고리 탭

- 타이틀 박스 아래 `24px` 간격으로 배치한다.
- 페이지 좌측에 붙인다.
- 스크롤 시 sticky 처리한다.
- 카테고리 탭에는 글래스모피즘 래퍼를 두지 않는다.
- 각 카테고리는 독립 버튼이다.
- 버튼은 `cursor-pointer`를 사용한다.
- 초기 active 값은 `전체`다.
- 클릭 시 active 상태를 변경한다.
- active 버튼은 검정 배경과 흰색 텍스트를 사용한다.
- inactive 버튼은 흰색 배경과 검정 계열 텍스트를 사용한다.

카테고리 순서:

1. 전체
2. 결혼식
3. 생일
4. 세미나
5. 돌잔치

버튼 스타일:

- `rounded-full`
- 가로 padding: `32px`
- 세로 padding: `12px`
- 버튼 너비는 내용에 맞춘다.

버튼 shadow:

```css
box-shadow:
  0 8px 24px 0 rgb(0 0 0 / 6%),
  0 2px 10px 0 rgb(0 0 0 / 8%);
```

현재 레이아웃에서는 sticky 기준이 내부 스크롤 컨테이너이므로, 의도한 시각 위치를 맞추기 위해 `top: -154px` 보정을 사용한다.

## 카드 클리핑

샘플 카드가 스크롤될 때 카테고리 탭 뒤로 비쳐 지나가면 안 된다.

카드는 카테고리 탭 아래 `24px` 지점에서 잘려 들어가는 것처럼 보여야 한다. 의도한 느낌은 “종이에 칼로 선을 긋고 그 사이로 카드가 들어가는 느낌”이다.

구현 기준:

- sticky 카테고리 영역에 배경과 동일한 커튼 레이어를 둔다.
- 커튼 레이어는 탭 하단 `24px` 영역까지 덮는다.
- 커튼 레이어는 탭 위쪽으로도 충분히 확장해서 헤더와 시각적으로 이어진다.
- 공통 헤더와 타이틀 박스는 커튼보다 위에 렌더링한다.
- 카테고리 버튼도 커튼보다 위에 렌더링한다.

현재 값:

- sticky 카테고리 위치: `top: -154px`
- 커튼 상단 확장: `240px`
- 커튼 하단 확장: `24px`

## 갤러리 그리드

- 카드 크기: `240px × 520px`
- 최대 한 줄 7개
- 가로 gap: `26px`
- 세로 gap: `40px`
- 7개 기준 전체 그리드 폭은 `1836px`이다. (`240px * 7 + 26px * 6`)
- 풀화면에서는 한 줄에 7개가 보여야 한다.
- 화면 폭이 줄어들면 한 줄에 들어가는 카드 수가 자연스럽게 줄어든다.

초기 구현에서는 실제 샘플 데이터 연결 전까지 큰 블록 플레이스홀더로 잡는다.
